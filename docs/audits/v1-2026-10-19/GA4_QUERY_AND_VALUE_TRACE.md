## Direct consumers and limits of the new findings

### Additional registered and retained service paths

`getCampaignValues:2576–2766` reads the campaign's selected stored property, tries sessionCampaignName, sessionManualCampaignName, campaignName, firstUserCampaignName, firstUserManualCampaignName, manualCampaignName until the first populated dimension, then additionally reads pageLocation UTM campaign names. Queries end today, sort by totalUsers, cap at200 and ignore provider rowCount/offset. Placeholder names are removed. Names merge case-sensitively using the maximum across dimension and URL aggregates; URL user counts sum page rows, so these displayed ranking hints are not guaranteed unique-period campaign users. Every non-auth error is swallowed into an empty contribution; after token refresh even repeated auth errors are swallowed. No cancellation signal is passed.

**V1-076:** [two exact-service cases](ga4-campaign-discovery-reproductions.json) show seven429 responses becoming `{campaigns:[]}`, and rowCount201 becoming200 names with no completeness marker or next page. Guarded route13223–13308 wraps these as success. New campaign wizard1111, GA4ConnectionFlow126 and child financial mapping wizards call this API. Reconnect filter render382–475 offers manual entry only when the returned list is empty; a nonempty incomplete list cannot be supplemented there. It labels a failed query as no UTM campaigns found and Select All means only returned names. No live Google request was used. Saved scope without an explicit property is overlaid by the route, preserving missing saved names with users0; this does not repair discovery or prove measured zero. Full discovery/failure state and a truthful selection contract are required independently of account/property pagination V1-038.

`getGeographicMetrics:2770–2861` queries country/region/city with users/sessions/pageviews/average session duration, top50 by users, requested lookback through today, session campaign filter. It returns individual location rows and labels the first10 `topCountries`; it does not aggregate countries or page beyond50. Current ga4-metrics4902 query is enabled for connected non-validation reads and refreshes on focus/reconnect/every10minutes, but no later reference rendering `geographicData` or `geoLoading` was found in that page. This is an active API/query cost and retained response contract, not proof of a currently visible geographic table. Real quota/load and optional-consumer checks remain required.

`getMetrics:3586–3796` supplies retained live metrics and fallback consumers: historical no-dimension sessions, pageviews, bounce rate, average session duration, conversions, users/new users, engaged sessions/rate and event count. Realtime runs only with no campaign filter and remains separate from historical totals. Session-filter historical query may fall back to exact UTM if no positive data; both include today. Counts use parseInt, rates/durations parseFloat and arithmetic average across response rows; impressions aliases users and clicks aliases sessions for the legacy response shape. userEngagementDuration is hard-coded0. These labels/units must not be reused as paid-media metrics. `getMetricsWithAutoRefresh:3491` refreshes authentication failures, not403 permission errors, and retries outside the token-refresh catch so provider failures are not always mislabeled reconnect. Missing tokens still throw; no fabricated provider data is claimed from this method. Callers include legacy metrics route10642, Executive API32921 and the non-saved-overview report branch541; current saved publication paths are distinct.

`getOverviewDimensionDiagnostics:1605–1730` is requested by the guarded breakdown debug branch13760. It requires nonempty selected campaign scope, makes separate six-dimension traffic/event queries plus UTM/date/campaign/landing queries, checks currency, and returns each query's status/totals/row sums. Rows are bounded1000 without pagination, so the debug diagnostic output is not authoritative campaign totals by itself. Direct fetch in discovery/geographic/legacy metrics/debug also bypasses the common abort/retry helper (V1-025); the existing direct-total reproduction demonstrates that transport distinction, not every branch's behavior.

`getLandingPagesWoWReport`, `getConversionEventsWoWReport` and `simulateGA4Connection` have no current tracked non-test callers found outside their declarations. Their definitions are retained in the service inventory; they are not counted as current scheduled or visible calculations. Runtime callers, provider API evolution or later activation would require independent review.

## Reuse and remaining evidence

### V1-090: provider data-quality metadata is discarded

Current-code search found no handling of `dataLossFromOtherRow`, `samplingMetadatas`, `dataTruncationReasons`, `schemaRestrictionResponse` or `subjectToThresholding` in tracked non-test analytics code. The `emptyReason` occurrences found belong to diagnostic-history presentation, not provider responses. Currency/timezone metadata validation is present and remains a useful separate guard.

Google's response contract identifies sampled results, truncation, active metric restrictions, other-row data loss and empty-result reasons. A threshold-subject flag can be present even when no data is omitted, and other-row metadata describes the underlying aggregate table, potentially beyond the final filter. Therefore these flags require an explicit acceptance/availability/provenance policy; they are not proof that every returned value is numerically wrong. [Official ResponseMetaData contract](https://developers.google.com/analytics/devguides/reporting/data/v1/rest/v1beta/ResponseMetaData).

[Eight exact-service cases](ga4-quality-metadata-reproductions.json), [runner](ga4-quality-metadata-reproductions.cjs), establish:

- `getTotalsWithRevenue:1392–1604` accepts six flagged fixture responses and returns normal totals without the quality fields: sampling10/100 events, other-row loss, threshold subject, active Revenue restriction, date truncation, and an explicit provider empty reason. The Revenue-restricted fixture returns revenue0; the reasoned-empty fixture returns zeros. No live provider behavior is inferred from those injected responses.
- `getAcquisitionBreakdown:1732–2573` accepts returned rows with sampling/other-row flags but does not preserve those flags in its API metadata.
- `getTimeSeriesWithToken:3044–3433` likewise returns daily rows without the response-quality flags.

Native publication reconciliation compares numerical daily/detail totals and scope before writing. It cannot reconstruct metadata already discarded by these service methods; agreement between derived totals alone does not prove an unsampled, unrestricted or untruncated provider result. No full scheduler publication was executed for these flagged cases, so this finding is specifically proven at the service/metadata-loss boundary, with downstream certification blocked until it is handled. Real current-account sampling/restriction/truncation occurrence remains external.

Acceptance: define provider-specific handling for each quality condition, preserve the necessary provenance through current saved publications/API/consumers, distinguish restricted/empty/partial from measured zero, and add corresponding native-publication/downstream negatives. Retain independent currency, pagination, date and numerical reconciliation guards. Future providers need their own completeness/quality indicators; GA4 flags cannot be copied as universal semantics.

Exact row-key joins, same-attempt scope capture, finite-zero-preserving finance, explicit incomplete validation, cancellation-aware provider calls and pre-write publication reconciliation are reusable safeguards only at their proven boundaries. Do not copy first-user fallback, GA4 UTM semantics, totalRevenue/purchaseRevenue rules, daily user sums, date presence or conversion definitions into Meta/Instagram/TikTok without independent provider validation.

Current suite includes Overview landing/conversion/campaign-breakdown, daily alignment, Insights coverage and report regression files. Their individual failures remain in [the ledger](VALIDATION.md); structural tests do not prove provider behavior. New query fixtures add coverage of missed paths and do not waive existing failures. All lifecycle/currency/source mixes, provider quotas/permissions, real empty/large properties, fractional conversions, sparse histories and rendered/scheduled artifacts remain required acceptance dimensions. Additional current-code review continues against the main inventory.
