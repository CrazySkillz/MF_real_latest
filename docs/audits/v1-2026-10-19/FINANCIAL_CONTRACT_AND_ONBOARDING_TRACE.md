## CSV Revenue lifecycle and input contract

Current owner-guarded route4735-5275 is distinct from Custom Integration CSV parsing. It validates mapping/header separation, selected campaign values, strict GA4 amount/date rules and a total ceiling. GA4 CSV parser uses strict overflow rejection. Edit without file requires full stored rows, or sample only when recorded count proves the sample is complete; changing stored value/date/campaign columns requires re-upload. Full normalized raw revenue/date/campaign rows are stored in mappingConfig; sample25 is only preview support.

Selected positive revenue rows are summed by date and optional exact mapped campaign key. Nonpositive rows are not materialized; all-zero input fails “No valid revenue rows”/empty-record validation. This is the actual supported input contract, not support for arbitrary zero/refund ledgers. Native negative-revenue support and imported positive-only CSV are different contracts and need explicit scope decisions. Mapping currency must equal campaign currency; `$` accepted only for USD by strict helper. Without date, records are assigned latest completed reporting date. Importing another file is additive; editing exact source replaces its records transactionally. Source-to-date and completed-day response totals are separately returned.

After source commit the route attempts downstream recompute but catches failure and still returns import success (5116). Publication invalidation can prevent stale output being treated as current, but UI/source/list/diagnostic recovery after that failure needs an explicit acceptance case. In-flight duplicate-add guard is process memory and removed in finally; it is not durable idempotency for a retry after lost success response or across instances. Existing transaction tests with missing `tx.select` mocks remain failures in the ledger; code trace does not waive them.

## CSV Spend and Google Sheets: independent processing paths

[Five exact-handler cases](spend-import-reproductions.json) establish defects independently of Custom Integration and Revenue CSV. Owner middleware/storage/recompute are fixture boundaries; actual current parser/date/numeric code executes.

- GA4 CSV Spend route6506 accepts approximate line counts up to50,005 but calls non-strict `parseCsvText(text,50000)`. Header counts toward the parser limit. A file with50,000 data rows of spend1 returns success and persists49,999. No truncation flag. Unlike Revenue CSV, this handler has no strict amount validator: `12oops` becomes12 via `aggregateCsvSpendRows`163; exact fixture persists it. Duplicate/blank CSV headers and width checks are also strict-mode-only. Date is required for new GA4 sources; exact source edit can preserve old undated contract. Stored full rows support edits, but truncated input cannot be recovered from stored rows.
- Google Sheets Spend preview6765 and process6905 always fetch `A1:ZZ5000`; no tab-size check, continuation or overflow detection. Fixture with5,001 data rows imports4,999, returns success and persists incomplete total. `parseNum`1456 accepts numeric prefix `12oops` as12. If all selected values are nonnumeric, process writes a zero record and success; measured-zero versus invalid-source distinction is lost. Both URL fetches have no abort signal, independently confirmed in fixture. These affect automatic refresh too because it invokes the same processing route; mapping guards do not prove data completeness.
- Sheets Spend checks current source mapping identity before refresh, exact campaign-owned connection, unique/missing mapped header names and dates, then replaces records in transaction. Those safeguards are real but do not repair omitted rows or permissive numbers.
- Sheets **Revenue** instead uses metadata/grid selection and5,000-row chunks up to50,000 total rows (`utils/google-sheets-revenue-ranges.ts`; route3149). It fails rather than silently truncating grids above that ceiling, preserves exact tab identity and quotes apostrophes in A1 ranges. Chunk response failures stop processing; credential refresh retries401. Range fetch uses formatted values (no UNFORMATTED_VALUE flag), so locale/currency strings remain part of the input contract. Amount helper accepts dollar symbols without campaign currency parameter, unlike GA4 CSV Revenue. Separate currency/locale acceptance still required.
- Revenue chunks concatenate returned rows; actual blank trailing rows may be omitted by provider, so reported preview row indices need checking against original sheet row numbers. Empty/missing mapped Revenue headers and duplicate headers are not validated by the same unique-header check present in Spend. Validate schema drift independently for each direction. No unsupported claim that all Sheets paths share one parser.

For all financial sources, active-source inclusion, exact replacement and publication fencing do not prove provider completeness. Required fixtures include boundaries immediately below/at/above caps, duplicate headers, malformed/locale amounts, zero/negative/blank values, source-date changes, failed recompute, lost-response retry and concurrent source edits. Use exact input counts/totals and reconcile source modal, completed-day cards, KPI/Benchmark, diagnostics and artifacts after each lifecycle action.

## Connection status, restart and fabricated fallback

`GET /api/campaigns/:id/ga4-connection-status`12891 prefers process-memory realGA4Client, then global OAuth map, then DB. In-memory branch does not recheck a persisted connection. `DELETE /api/ga4-connections/:connectionId`16075 checks actor/campaign and deletes storage, but neither it nor `storage.deleteGA4Connection` clears those maps. A disconnect can therefore leave status “connected” until process state disappears. No runtime caller of `realGA4Client.disconnect` was found.

`real-ga4-client.ts:198-258` returns four hardcoded property choices when live property discovery returns no properties/fails. The current status response calls these **Real Google Analytics API**, `connected:true`. Exact method+handler fixture proves that result and zero DB reads. It is a currently reachable fallback: the primary callback populates realGA4Client, and the current component queries status on mount. Existing in-memory availableProperties cache can hide the defect until empty/error path. Startup/reset changes which branch responds; neither memory nor a database row proves current permission. Do not reuse this fallback as the future-provider template.
