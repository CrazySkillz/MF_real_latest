## Browser report gate and artifact boundary

`downloadGA4Report:3434` refuses pending/failed publication. It checks selected sections against aligned financial snapshot identity, amounts/conversions/spend, currency, reporting date/start/timezone. Overview needs selected summary/revenue/spend/campaign/landing/event inputs; absent spend source is handled separately from unavailable spend. Ad Comparison requires its appropriate Overview-derived top rows, independent native detail and imported provenance3500. A custom report can select subsets, so tests must cover each allowed subset and its minimum inputs.

Source-to-date Revenue Breakdown labels and completed-day scheduled output are not assumed identical. Browser generation uses current UI data and choices; scheduled generation has separate preflight, window and PDF code. GA4 snapshot downloads use persisted artifacts; retained platform snapshots do not (V1-060). Needed acceptance: exact PDF numbers/source IDs/labels/windows, empty and negative inputs, all selected sections, long names/rows/pages, UTF-8 content, fresh/stale transitions and later immutable download. No rendered full-source PDF packet was produced without the required authenticated test context.

## Reusable safeguards and limits

Exact mapping keys, ambiguity/currency/materialization checks, independent availability, input-specific report gates and preserving last-good display are reusable contract examples in the existing architecture. They must be independently exercised for each new source. Provider-specific session key-event rate versus event conversion rate, GA4 daily users, revenue fallback, import-start/completed-day windows and CRM allocation keys cannot be copied as universal definitions. Native positive controls and existing regressions support these individual patterns; current failing tests and unverified provider/consumer cells prevent calling GA4 the certified future-source template.
