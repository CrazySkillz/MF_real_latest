## Findings and executable boundaries

**V1-104 — inconsistent monetary windows (P1).** Source list `routes-oauth.ts:3679–3735` queries1900–2999 for non-GA4 contexts; exact-handler fixture confirms both all-history reads. Instagram374–382, Google Ads499–508 and Meta658–668 select these source totals before the bounded totals API. Each exact page case receives all-history Revenue900, bounded Revenue100 and period Spend100; it selects900, ROAS9 and ROI800%, rather than the matching-window ratio. Meta's live provider range and Instagram's metrics are30days; their fallback Revenue request is90days. Google Ads additionally uses90 elapsed days plus both endpoints while `getDateRangeBounds('90days'):1501` uses90 inclusive UTC dates. TikTok independently requests1900-through-today Revenue beside30-day rows; its response does not identify the different financial window. Keep source-to-date displays where intended, but match numerator/denominator and label each interval. Test dates at both boundaries, older imports, exact-zero/current-only data and all downstream outputs.

**V1-105 — storage failures become successful empty analytics (P1).** Instagram daily25370, overview25294 and TikTok25212 catch daily-row DB errors as[]. Actual Instagram/TikTok daily handlers return200/success=true/rows=[] for a thrown DB failure; TikTok states that no persisted rows exist. The page has genuine HTTP error controls, but these cannot detect swallowed errors. This is a failure-to-empty defect; the packet does **not** claim the Instagram overview renders measured-zero cards when no rows exist. Preserve explicit failure/stale last-good state and recovery without fake test rows. Instagram's test_mode branch can seed rows after the caught failure if later writes succeed; that branch was not executed here.

**V1-106 — currency guard fallback and labels (P1).** Storage3093/3164 explicitly rejects mixed source/record currencies. Source-list3679 catches both breakdown errors, then returns mappingConfig.lastTotalRevenue with success=true for non-GA4 sources. Exact handler/page case supplies USD100 and EUR200 mapping totals with the actual currency-error text; Instagram sums300 and computes ROAS3. This is a conditional persisted-data case, not evidence those sources exist live. Separately current Google Ads699, Meta622, TikTok104 and Instagram70/1076–1100 format monetary values with a literal dollar sign, although imported sources and TikTok financialSummary can carry EUR. Four exact formatter cases show100→$100.00; no FX conversion occurs. Google Ads status27064–27084 omits currency, while the current Revenue wizard2768 reads connection.currency and defaults USD; the status response control confirms the absent field. Preserve currency identity, reject incompatible sums, keep errors unavailable, and use authoritative selected currency through setup/cards/KPIs/Insights/PDFs. A formatter change alone does not close the fallback defect.

**V1-107 — ratio aggregation loses denominator (P1).** Google Ads page511–539 averages per-row CTR while Overview computes CTR from summed counts. Same-day rows1000 impressions/10 clicks/CTR1% and10 impressions/10 clicks/CTR100% produce chart50.5% versus actual20/1010×100≈1.9802%. Summary492 and chart536 also average Search Impression Share without its eligible-impression denominator. The synthetic exact Search example yields75% versus1010/2010×100≈50.2488%. The official metric is received Search impressions divided by estimated eligible impressions; values below10% are returned as0.0999, not an exact9.99%. Current provider306 rounds that sentinel to9.99 with no bound metadata. [Official Google Ads v25 metric contract](https://developers.google.com/google-ads/api/fields/v25/metrics?hl=en), [Google's definition](https://support.google.com/google-ads/answer/2497703?hl=en&product=sales). Do not implement naive eligible-count reconstruction from rounded/censored/mixed-network shares. Obtain provider aggregate at the correct grain or show explicitly limited/unavailable results; preserve bound semantics and reconcile charts/targets/Insights/reports.

**V1-108 — measured-zero TikTok Revenue becomes unconfigured (P1).** API25238–25258 requires totalRevenue>0, and page839 repeats that requirement. Fixture supplies totalRevenue0, EUR and sourceIds containing an existing source; response replaces the amount with null and says a source is required. With positive Spend, valid zero Revenue should permit a measured loss/zero ROAS under the applicable contract; absent source, failed read and valid zero must be distinguishable. The handler separately catches revenue-read failures as0, so simply changing the inequality would introduce another failure-to-zero path. Fix availability/provenance together in the existing API/page flow.

## Scope limits and next acceptance

These findings add concrete value/negative-state evidence to the retained-source ledger. They do not make every field on those pages reviewed end to end: full KPI/Benchmark lifecycle, rule thresholds, source mutation/late refresh, mixed-provider ownership, report configuration/delivery, every table/export cell, and representative browser layouts still need acceptance or an effective agreed exclusion. Source-family/provider gates remain separate; do not implement Instagram/TikTok/Meta now as a shortcut to V1. Their existing routes/jobs must be safely handled as part of the current release boundary.
