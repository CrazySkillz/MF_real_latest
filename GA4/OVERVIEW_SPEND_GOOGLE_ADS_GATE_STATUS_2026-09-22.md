## Confirmed root cause and local fix

The Spend wizard saves selected Google Ads campaign IDs in the GA4 spend source's `mappingConfig`. It does not call the separate Connected Platform `/selected-campaigns` route. The four-hour provider refresh previously read `google_ads_connections.selected_campaign_ids`, and the subsequent GA4 Spend materializer rejected a saved source whenever that connection field differed. A normal GA4 Spend import could therefore succeed but fail its next scheduled refresh, leaving the source stale.

`server/google-ads-scheduler.ts` now reads the one active GA4 Google Ads Spend source's saved selection for Spend-only provider refresh. Before a source exists, the initial customer fetch can still list the account data for the chooser. A present source with no selection, or multiple active GA4 Google Ads sources, fails before provider daily metrics or Spend records are replaced. The materializer uses that same source selection and no longer treats the separate connection selection as authoritative. A source-inventory read error now propagates as a refresh failure instead of being misreported as an absent source. The non-Spend Connected Platform selection branch and response contracts are unchanged. Focused tests cover divergent connection/source selections, missing/duplicate saved scope, and source-read failure; they use mocked provider facts and do not prove live correctness.

A later check found that a source named `Google Ads` with a missing `mappingConfig.platform` was ignored by the Spend-only provider refresh. That could fetch all account campaigns before the materializer skipped the source. The Spend-only branch now recognizes the named source and rejects its invalid mapping before provider fetch or daily-row replacement. The no-source initial fetch remains allowed. The separate Connected Platform branch is unchanged.

The Spend dialog also performed a second full provider refresh immediately after `select-customer` had already fetched and saved the initial daily rows. If that duplicate request failed, the dialog reported a failed connection even though the account had been saved. `client/src/components/AddSpendWizardModal.tsx` now proceeds from the successful customer selection to the saved-data campaign preview. This changes only the GA4 Google Ads Spend dialog; the scheduled refresh and Connected Platform UI remain on their existing paths.

The Spend source chooser previously did not read the saved Spend-only connection, so it could not show `Connected`, refresh the provider data, or safely remove that connection. The local candidate now reads the existing `spendPreview=1` status, exposes the existing Spend-only refresh route, and adds a confirmed disconnect action. The new campaign-guarded disconnect transaction deactivates the exact GA4 Google Ads Spend source, deletes only its Spend records and dedicated provider facts, and removes only dedicated or legacy `spendOnly=true` OAuth rows. It fails closed if multiple active matching sources exist and preserves the separate Google Ads Connected Platform, other Spend sources, and other campaigns. A connected account with no provider spend is labelled `No campaigns with spend found yet`; no zero-spend source is invented.

After deployment, the user's newly created Google Ads campaign still had no reported spend. The daily preview correctly returned an empty successful result, but the client displayed it as a destructive `No data found` error. The follow-up keeps real HTTP/API failures destructive while presenting a successful empty Google Ads refresh as `No spend yet`. It does not create a source, amount, or provider row from zero activity.

The customer selection route used a shared per-campaign Google Ads connection row. A Spend-only selection could delete and replace an existing main Google Ads Connected Platform connection and its daily rows. With the user's approval to proceed, the local candidate now writes Spend-only credentials and daily rows to separate GA4 Spend tables. The Spend modal requests `spendPreview=1` for its connection status and daily preview; the default Connected Platform API path still reads the original tables. The scheduler inventories and refreshes both roles separately. An active Spend source blocks a reconnect to a different customer until that source is deleted. Legacy Spend-only rows in the original tables remain readable; no production rows were moved. The existing startup migration sequence now creates the two new tables and indexes using the same definitions as migration `0017`; actual database coexistence and successful deployed migration remain unproven.

The user then approved the shared-client dependency change. `server/googleAdsClient.ts` now targets Google Ads API `v25` and reads all `SearchStream` response batches for customer metadata, account campaign lists, and daily rows. A malformed stream envelope fails closed instead of becoming a zero-row response. Google's v22 rename of `metrics.video_views` to `metrics.video_trueview_views` is applied in the provider query while the app's existing `videoViews` field remains stable. The client still returns the same types to its callers. `server/googleAdsClient.test.ts` covers multi-batch customer/campaign/daily results, the v25 URL, selected-campaign filtering, micros-to-spend aggregation, renamed video metric, and malformed batches. See Google's [Search and SearchStream](https://developers.google.com/google-ads/api/rest/common/search), [v25 campaign fields](https://developers.google.com/google-ads/api/fields/v25/campaign), [v22 release notes](https://developers.google.com/google-ads/api/docs/release-notes), and [sunset dates](https://developers.google.com/google-ads/api/docs/sunset-dates).

Changed files: `client/src/components/AddSpendWizardModal.tsx`, `shared/schema.ts`, `migrations/0017_add_ga4_google_ads_spend_storage.sql`, `server/index.ts`, `server/storage.ts`, `server/google-ads-scheduler.ts`, `server/googleAdsClient.ts`, `server/routes-oauth.ts`, `server/googleAdsClient.test.ts`, `server/google-ads-spend-production-path.test.ts`, `server/ga4-google-ads-scheduler-regression.test.ts`, `server/google-ads-spend-lifecycle-downstream.test.ts`, and this note.
