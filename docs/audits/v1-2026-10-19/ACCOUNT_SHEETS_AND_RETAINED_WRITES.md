## Account and authorization

- `index.ts:68` installs Clerk identity middleware, not global required authentication. `ensureCampaignAccess`3366 checks actor, parsed ID, existing parent, nonempty exact owner; missing/foreign owner is404. Verified internal requests use random process-local token plus socket loopback and timing-safe equality (`internal-request-auth.ts`). Scope header additionally requires internal authentication and structured campaign/owner/work/lease values. This header is not a public owner override.
- Session/KPI/Benchmark/report helpers8824-8934 resolve the resource's stored campaign then authorize it; unscoped platform rows are404. LinkedIn sessions additionally require a current connection. Direct routes that bypass these helpers remain findings001-006/034. Guard presence alone is not proof that an update cannot move the resource afterward.
- Campaign create/update checks client ownership; update explicitly removes ownerId, and uses current campaign ownership. Ordinary writes use GA4 input-change transaction and invalidate existing durable work/publication markers. Campaign filter/timezone changes additionally clear GA4 daily/overview rows. Exact same-owner client move, currency/date changes, cancellation/draft activation and reload remain distinct value/recovery gates; not all have browser proof.
- **Retained reparenting defect (V1-054):** LinkedIn update28649 parses insertLinkedInConnectionSchema.partial(), which includes campaignId, then storage4445 spreads that into .set. Legacy Meta KPI26553 and Benchmark27630 pass raw request updates to storage5312/5341. All authorize only the original parent. Three exact handler fixtures check only owned campaign then pass foreign replacement campaignId into persistence. No foreign database was touched. Modern shared KPI/Benchmark branches explicitly discard campaignId/platformType; Meta report27739 discards identity fields, so they are not included in this defect.
- Frontend `App.tsx:175` keeps the singleton query client outside SignedIn/SignedOut. `queryClient.ts` staleTime=Infinity, `clientContext.tsx:16` keys clients solely by `/api/clients`, and selected client localStorage key is not account-specific. No query clear/removeQueries or identity-binding code was found in tracked client TSX. Real TanStack fixture returns owner-A cached clients without invoking an owner-B fetch for the same key (V1-052). This proves cache behavior, **not** live Clerk account-switch execution; a hard page reload may reset memory. Signed-out UI gating does not itself erase the cache.
- `rateLimiter.ts` exposes caller body.isTestMode=true as a skip for OAuth, LinkedIn and imports, independent of environment. Exact skip-function fixtures confirm all three bypass (V1-053). General and GA4 limiter definitions do not establish application coverage; their actual attachment must be part of the load/abuse acceptance matrix.
- Logging code writes full custom request bodies, webhook/email tokens, attachment URLs, sender/subject and parsed metrics (`routes-oauth.ts:28000,28249-28251,28376-28378,28459`). Global API logger166 serializes responses before truncating logged text to80 characters. Truncation is not structured redaction and path itself can contain a bearer token. Deployed log access/retention/existing exposure was not inspected. Custom ingestion's confidentiality boundary remains V1-026; no secrets were collected in audit artifacts.

## Standalone Sheets (separate from GA4 financial Sheets)

- OAuth/service-account selection, tab lists, multi-tab selection, mappings, primary connection, refresh, transfer and disconnect all have retained routes (inventory). Metadata/tab list16847 is campaign-guarded; it chooses newest pending/matching credential with purpose fallback. That is discovery authorization, not a bound selection certificate. Source IDs and purpose must stay exact in later financial reads.
- Main GET21785 permits only active general-purpose connections when campaign platform includes Sheets. Requested composite spreadsheet/tab/connection lookup can fall back first to any matching spreadsheet, then primary/first connection21834-21842. Thus a stale exact tab request may silently return another tab. No cross-tenant access is claimed: fallback stays within the authorized campaign, but source identity is wrong.
- Main GET21987 and automatic refresh `auto-refresh-scheduler.ts:813` request A1:Z1000; no whole-sheet completeness check. Main response23112 includes a row-limit warning and separate lastDataRefreshAt; automatic cache publishes999 data rows with a fresh timestamp, confirmed by exact fixture. The warning does not make downstream totals complete. Empty provider response skips cache replacement, retaining prior rows; metadata does not distinguish deleted/empty sheet as zero versus refresh failure.
- Summary row selection22245+: saved mapped campaign values use exact normalized set; otherwise substring campaign matching is allowed. If no match and no explicit mapping, rowsForSummary falls back to all rows. When campaign/platform columns are unavailable, all rows also contribute. These fallbacks must not be represented as exact campaign attribution.
- Column summary excludes identifiers/date-like headers, samples numeric detection and aggregates detected values. Legacy summary chooses Spend(USD)/Budget/Cost by truthiness and CTR from summed clicks/impressions. Arbitrary mapped count/rate/duration fields need explicit aggregation contracts; summing or averaging by label is not evidence of metric semantics.
- `buildGoogleSheetsPlatformSourceForAggregate`75 sums mapped cached rows across connections with **no campaign-row/date filter**, reports newest lastDataRefreshAt across the group, and gates financial metrics by confirmed source IDs. includeCachedMetrics=true also bypasses exactCurrencyVerified check; callers scheduler436 and executive32992 use defaulttrue, current-window aggregate15414 can passfalse. Caller-side financial checks must be traced before inferring a mixed-currency display defect. Counts/sessions/users from a partial cache are not complete provider values.
- GET can write conversionValue when AUTO_CALCULATE_CONVERSION_VALUE enabled: platform connection22912/22917, campaign23039, latest LinkedIn session23053, or clear campaign value23072 for multiple platforms. Default/flag configuration and exact read side effects must be recorded; a page fetch is not automatically read-only. Mixed platform denominators and fallback totals require separate parity tests.
- Mapping save34765 validates owner/connection and mappings, persists config first, then recalculates from selected/fallback mapped sheets and latest LinkedIn data. Downstream failure can occur after mapping save. Retained transfer33626 checks both owners but copies only credential/spreadsheet fields, omitting sheetName/purpose/mappings/cache/selection, then deletes old row in separate calls. No current UI caller has been proven for transfer; it remains reachable and not safe to remove without compatibility inventory.
- GA4 Revenue Sheets uses chunking/strict amount/date and source transaction paths; GA4 Spend uses a separate fixed5000 range/permissive parser (V1-041). No shared label or helper proves these three families equivalent.

## Retained paid Spend import

`POST /api/campaigns/:id/spend/ad-platform/import`27325 checks parent owner but Google Ads/Meta/LinkedIn branches fetch every stored daily row for the date range without selected-ID/connection eligibility checks. TikTok has a separate selection guard. It writes hard-coded USD source/records, deletes then inserts without atomic replacement, and recomputes campaign spend using getSpendTotalForRange's defaultGA4 context rather than the imported platform. Exact fixture with EUR campaign and selected10/unselected90 returns100 and storesUSD (V1-055). GA4 dedicated Ads Spend safeguards do not cover this retained route.

## Remaining gates

Two-user API and actual Clerk browser transitions, every source selection/transfer/disconnect/reconnect edge, partial/empty/provider error distinction, financial/source window parity, all retained mutation schemas, cross-worker deletion/refresh, log redaction and deployed configuration remain separate requirements. Evidence above proves listed defects and bounded guards; it does not certify all access or Sheets semantics.
