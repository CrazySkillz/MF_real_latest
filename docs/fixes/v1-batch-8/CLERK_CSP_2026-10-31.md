# Production Clerk browser-policy correction

Scope: the smallest code prerequisite for launch task 1 / V1-013. This does
not switch Clerk instances or close production sign-in acceptance.

## Root cause and traced path

`client/src/main.tsx` supplies `VITE_CLERK_PUBLISHABLE_KEY` to `ClerkProvider`.
Clerk loads its script and API from the hostname encoded in that public key.
`server/index.ts` sends the production Content-Security-Policy for the app page;
its fixed `script-src` and `connect-src` allowlists omit custom Clerk production
hostnames. The browser therefore blocks the script/API before sign-in can work.
[Clerk's required CSP sources](https://clerk.com/docs/guides/secure/best-practices/csp-headers)
confirm this configuration requirement. The installed Clerk key parser confirms
the base64 hostname plus trailing `$` format; no private key or session is used.

## Minimal correction and preservation

`server/index.ts` adds only the exact HTTPS hostname from a valid configured
frontend `pk_live_` key to those two directives. Strict DNS-label, total-length
and delimiter checks reject wildcard, path, port and header/directive injection.
Missing, malformed and existing test keys leave the policy unchanged. Other
directives, headers and environment gating are unchanged. No dependency, schema,
auth middleware, ownership, provider callback, data, calculation or schedule changes.

The extended `server/security-headers-regression.test.ts` executes the actual
header block without app startup or database access. Its isolated Chromium test
uses intercepted synthetic hosts, never a personal browser or real provider.
[Before correction](validation-2026-10-31-clerk-csp/before.json): three reproduced
failures, including blocked custom-host script/API; fifteen controls pass.
[After correction](validation-2026-10-31-clerk-csp/focused.json): **84/84 checks
pass in five files**, including existing authorization, callback and scheduler
startup controls. Chromium permits the configured custom host and existing
Google/development Clerk resources while still blocking an unrelated origin.
TypeScript and the server build pass. [Validation summary](validation-2026-10-31-clerk-csp/validation-summary.json).
